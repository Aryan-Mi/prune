PRune

Prune generated files out of GitHub pull requests.

General

On the "Files changed" tab

Pruned file diffs
Pruned files in the file tree

Your rules

One pattern per line in .gitignore syntax. Your rules are applied after the built-in and repository rules, so they win. Start a line with ! to keep a file that another rule prunes.

Type a file path to see which rule applies.

Rules file URL

Point PRune at a .pruneignore-style file you keep elsewhere, like a dotfiles repository or a gist (use the raw URL). It's fetched in the background and refreshed every hour, so editing that file updates PRune without touching these settings.

Built-in rules

Sensible defaults for files nobody reviews by hand. Switch off any group you want to see.

Disabled repositories

Turn PRune off for a repository from the toolbar popup while viewing one of its pull requests.

    Sharing rules with your team

    Commit a .pruneignore to the repository root (or .github/pruneignore). Everyone using PRune picks it up automatically. Same syntax as above: 

    # Generated API client
packages/api-client/src/generated/

# Database migration snapshots
drizzle/meta/*.json

# We do want to review lockfile changes in this repo
!pnpm-lock.yaml
